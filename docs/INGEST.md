Приймання даних у чергу:

Приймач це API Gateway (HTTP API) з функцією Lambda, яка кладе повідомлення в чергу SQS. Код функції у functions/ingest/index.js, інфраструктура в terraform/ingest.tf і terraform/queue.tf.

Запит:

POST /ingest
Заголовок x-api-key: ключ API (генерується Terraform, лежить у SSM Parameter Store, у репозиторії його немає).
Заголовок Content-Type: application/json

Схема повідомлення:

sensor_id: рядок, ідентифікатор датчика, до 64 символів.
sensor_type: temperature, humidity або light.
value: число.
unit: рядок, одиниця виміру (наприклад C, % або lux).
location: об'єкт з lat (від -90 до 90) і lon (від -180 до 180).
measured_at: час вимірювання в UTC, формат ISO 8601, наприклад 2026-11-19T19:30:00Z.

Приклад:

curl -i -X POST $URL -H "x-api-key: $KEY" -H "Content-Type: application/json" -d '{"sensor_id":"temp-01","sensor_type":"temperature","value":21.5,"unit":"C","location":{"lat":50.45,"lon":30.52},"measured_at":"2026-11-19T19:30:00Z"}'

Адресу і ключ беруться з Terraform:

URL=$(terraform output -raw ingest_url)
KEY=$(terraform output -raw api_key)

Відповіді:

202 Accepted: повідомлення прийняте і лежить у черзі. Тіло містить ідентифікатор повідомлення в черзі, наприклад {"status":"accepted","message_id":"ef0bf902-954d-444e-83a7-63b9df991ea6"}.
400: некоректний JSON або поле не пройшло перевірку. Тіло містить опис помилки, наприклад {"error":"sensor_type must be one of temperature, humidity, light"}.
401: ключ відсутній або неправильний.
500: внутрішня помилка (недоступна черга або параметр з ключем).

Перевірка в приймача:

1. Ключ у заголовку x-api-key порівнюється з ключем із SSM (порівняння постійного часу).
2. Тіло має бути JSON-об'єктом.
3. Усі шість полів обов'язкові, типи і діапазони перевіряються.
4. До черги потрапляють лише відомі поля, зайві відкидаються.

Чому приймач не обробляє дані сам:

Приймач має лише швидко прийняти повідомлення і відповісти. Якби він ще й обробляв дані та писав у базу, відповідь датчику залежала б від швидкості обробки і бази. Під навантаженням запити б накопичувались, датчики отримували б помилки і втрачали вимірювання. Черга відділяє приймання від обробки: приймач відповідає за десятки мілісекунд, а повідомлення можуть почекати в черзі, поки функції обробки їх розберуть. Якщо обробка зламалась або працює повільно, дані не втрачаються, а лежать у черзі (до доби, як налаштовано). Кожну частину можна масштабувати окремо.

Захист приймача:

Від зловживань діє ключ API і ліміт запитів на рівні шлюзу (500 запитів на секунду, сплеск до 1000).
